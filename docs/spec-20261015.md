## 4. 状态机
状态：LISTENING / MAYBE_DONE / CUT_OFF_WAIT / THINK_WAIT / CONFIRMED。
- LISTENING → 判停 label：complete(且 margin 满足策略)→MAYBE_DONE；cut→CUT_OFF_WAIT；wait→THINK_WAIT。
- MAYBE_DONE：静音 ≥ `confirm_silence_ms` 且文本未变 → CONFIRMED。
- CUT_OFF_WAIT：静音 ≥ `cut_wait_ms` → CONFIRMED。THINK_WAIT：静音 ≥ `think_wait_ms` → CONFIRMED（不调 LLM 直到此刻）。
- 任意状态静音 ≥ `max_silence_ms` 或 KEV 超时 → CONFIRMED。
- 静音 = 从"最后一次文本变化"与 VAD speech_end 中较晚者起算。
- MAYBE_DONE/CUT/THINK 下来新文本或 speech_start → LISTENING，取消计时器；有在途投机 LLM → 作废（`llm_cancel`）。
- CONFIRMED → 调一次 `decide()`；若决策返回前用户又开口 → 作废结果，新文本并入本轮，回 LISTENING。动作已执行（mock）后再开口 → `barge_in`，开新一轮。
- "取消"= 放弃线程结果（token 照常消耗），不改模型客户端。
- `speculative_llm=true`（M3）：MAYBE_DONE 且 margin ≥ `spec_margin` 时立即带当前短名单调 LLM，被反转则作废，记浪费。

## 5. 事件（SSE 与 timeline.json 同一格式，每条含 `t_ms` 与 `text_version`）
`asr_update`、`eot_start`、`eot_scores`、`eot_skipped(reason)`、`tools_start`、`tools_scores`、`state_change(from,to,why)`、`llm_start(speculative)`、`llm_cancel(reason)`、`llm_decision`、`barge_in`、`turn_done`。
`turn_done` 汇总：`t_last_word, t_confirmed, t_llm_start, t_decision, eot_calls, eot_skipped, tool_calls, llm_calls, llm_wasted`。

## 6. 接口与 UI
**POST `/api/session/stream`**（SSE，按真实时间间隔回放）
请求：`{"updates":[{"t_ms":0,"text":"我去","final":false}], "vad":[{"t_ms":0,"kind":"speech_start"}], "config":{...TurnConfig 覆盖}, "tool_set":"navigation"}`；响应：逐条事件 `data: {json}`，最后一条 `turn_done`。旧接口保留。
**UI "流式模拟"模式**：输入文本 + 语速（字/秒）+ 停顿标记（`我去买菜|600|对了还要买酱油`，`|600|`=停顿 600ms），自动生成 partial 更新。时间线表每行：t、文本、三项分数、argmax/margin、状态变化、KEV 墙钟/自报耗时、工具 top-3；LLM 启动/作废/决策单独标色。能手动改 TurnConfig 关键字段。

## 7. 里程碑与验收

### M1 核心链路（脚本化 ASR 回放）
做：拆 `select_tools/decide`、`turn_eot.py`、`turn_session.py`、`/api/session/stream`、UI 模式。
**验收 A1（回归）**：`/api/run`、`/api/run/stream` 对原有样例输出与改动前一致（做一次前后对比）。
**验收 A2（单测 score_eot）**：`score_eot("导航回家")` 返回三个概率、label、wall_ms；"我想去"之类半句 label≠complete 或 cut/wait 分数更高（若不是，记录，不阻塞）。
**验收 A3（四个 V2 脚本，用 curl 打 `/api/session/stream` 并检查事件，另在 UI 人工看一遍）**：
1. `导航回家` → 恰好 1 次有效 `llm_decision`，`llm_wasted=0`。
2. `我去买菜|600|对了还要买酱油` → 600ms 停顿后若进了 CONFIRMED 并调了 LLM，则后续文本应触发 `llm_cancel` 并最终只有 1 次有效决策（作用于合并文本）；若 KEV 没把前半句判 complete，则不应出现 LLM 调用于前半句。无论哪种，最终有效决策恰好 1 次且基于完整文本。
3. `帮我导航到…|1500|…人民广场` → 前半句进 CUT_OFF_WAIT 或等待，不应在 1500ms 内调 LLM；后半句并入后 1 次决策。
4. `等一下我想想|2500|回家` → THINK_WAIT 期间不调 LLM；"回家"到来后 1 次决策。
**验收 A4**：`timeline.json` 生成，`turn_done` 汇总字段齐全；"选工具复用"生效（最终文本不变时 `tool_calls` 不增加）。
**M1b（仅当找到 ASR key）**：`eval/asr_stream.py` 提供 `stream_asr(audio_path|mic) -> yield (t_ms, text, final)`，接到 `TurnSession.on_asr`；验收：用一段本机 wav/macOS `say` 生成的音频，产出 ≥2 条 partial + 1 条 final 并走完一轮。没找到 key 则跳过并写明。
