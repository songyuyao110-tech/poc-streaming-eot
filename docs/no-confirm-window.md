# 去确认窗：判停三态、生成中打断、参数面板口径

> 一句话：**不再有「判完（不管判成什么）一律静默等 700ms」那一段整段确认窗**——判完「说完」就立刻往选工具 / 生成走；只有**「可能说完」**才稍微等约 0.7s 收敛，**任何一态最大超时 2s**。生成期间本席再开口＝打断本轮、作废本轮决策，但**话不丢**（半截 + 新话一起再送）。

**这一页管什么**：图、诊断面板、术语的**文案基准**（2026-11-04 用户拍板）。
**这一页不管什么**：不改状态机行为、不给新数字。落地实现与用例重锚归独立 Dev 单（「去窗单」）；本页写的是口径，不是「现在代码已经是这样」。截至 2026-11-04 本单一动笔时，`confirm_silence_ms` 在实现里仍是「判 complete 后整段等」的语义（`src/turn_session.py`、`docs/PROJECT-POC.md` §1.4.4）。

---

## 1. 判停之后怎么等：三态挂窗（口径表）

| 判停结果 | 往后怎么做 | 谁在等 |
|---|---|---|
| **说完**（强 complete） | **立刻往后**：进选工具 → 生成，**不等** | 没有人等 |
| **可能说完** | **稍微等约 0.7s**，看它是真说完还是还差半句；收敛了就往后走 | **只这一档**等约 700ms |
| **没说完**（cut / wait） | **继续听**：不选工具、不生成、不催 | 等用户继续说（cut 1.5s / wait 3s 是另一回事） |
| **任何一态** | **最大超时 2s** 封顶 | 上限 2s |

两句读法（最容易读错的地方）：

- **被撤掉的是「整条链路的确认窗」**：旧流程是判完不管判成什么，都无条件静默等 700ms 文本不动才往下走。现在**说完就立刻走**，没有这一段无条件等待。
- **被保留的是「可能说完」那一档的约 0.7s**：它不是确认窗回魂，是三态里一档的收敛等待。**别把「去确认窗」讲成「700ms 整段没了」，也别反过来说「确认窗还在」**——两种说法都被拍板否掉。

## 2. 生成中打断

- **打断落在生成上**：生成期间本席又开口 → 作废本轮、继续听；不是「改一改继续生成」。
- **作废的是决策，不是用户的话**：半截 + 新话一起再送（承接），不要求用户重说一遍。
- **落地即不可撤**：动作执行之后再说话属于**下一轮**；不用「执行前加一段等待」去换可回撤性（那会让每一次都更慢）。
- **不是 TTS 打断**：本项目不做播报，没有播报可打断。见 §4 的命名问题。

## 3. 参数面板口径（诊断页 / `ui/index.html`）

| 参数 | 面板口径 |
|---|---|
| `confirm_silence_ms`（默认 700） | **只应作用于「可能说完」一档**。把它当成「判完一律等这么久」的整段窗，是 2026-11-04 之前的旧口径。面板保留可改值＝**调试用**；把它调回整段窗等于回退旧口径，**不是主路径可加回的后门**，也不得写进验收口径 |
| `cut_wait_ms` / `think_wait_ms` / `max_silence_ms` | **不在本次撤除范围**：「话断了等 1.5s」「在犹豫等 3s」「静音 2s 兜底」是另外三个计时器，别顺手一起删 |
| `speculative_llm` / `spec_margin` | 投机的收益从「藏掉确认窗」变成「和生成重叠」；口径改写但开关不动 |
| 展示标签 | 时间线上原来的「判停确认 +Xms」在旧口径下含那 700ms；新口径下它是「判停 → 往后走」的耗时，**说完时应接近 0** |

面板上给读者的一句话（文案基准，别改意思）：

> 口径（2026-11-04 拍板）：说完 → 立刻往后；可能说完 → 约 0.7s；没说完 → 继续听；上限 2s。`confirm_silence_ms` 只该作用于「可能说完」一档，调成整段等待＝回退旧口径（仅调试）。

## 4. `barge_in` → `turn_reopen`（已改名）

- **曾撞名**：事件名 `barge_in` 与**打断 TTS 播报**（barge-in）撞名；本项目不做播报，读图 / 看诊断面板的人会误会成「我们能打断播报了」。
- **改名（2026-11-04 代码单）**：`barge_in` → `turn_reopen`（`src/turn_session.py` 里 `on_asr` 在动作落地 / 本轮收口后触发），语义不变：**用户又开口 → 开新一轮**。与生成中打断（`turn_void`，作废本轮）分开。

## 5. 数字口径（引用前先看这里）

`858.7ms`（单席 A0）、`877 / 876ms`（双席 A1）、`3243.7ms`（M4 端到端 p50）**全部是带窗口径量出来的**，不能当新流程实测，也不能按「少了 700ms」去推算新数。重锚归测评单（同批要处理的还有钉住 700ms 的 A0 / A1 / 文本用例期望）。
